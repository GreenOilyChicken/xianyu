# 闲鱼数据获取方案调研（2026-10-08）

> 起因：想拿自己账号的商品数据（浏览量、想要数、咨询量），像 bilibili 接口那样拉下来。
> 结论：**没有 bilibili 那种干净接口**，但有几条可行路径，代价和风险各不相同。

---

## 一、为什么闲鱼和 bilibili 不一样

| | bilibili | 闲鱼 |
|---|---|---|
| 公开 API | 有（`api.bilibili.com`，社区文档齐全） | **个人卖家数据没有公开 API** |
| 鉴权 | Cookie 即可，可长期复用 | 签名 + 设备指纹，Cookie 易失效 |
| 拿自己数据 | 直接 HTTP 请求 | 只能走**浏览器自动化**（模拟已登录操作） |
| 封号风险 | 低 | **高**（自动化操作真实账号） |

**关键点**：bilibili 能直接 HTTP 调是因为它有半公开的接口约定。
闲鱼的网页/App 接口有签名和设备校验，**所有能用的方案本质都是"用你的登录态模拟人操作"**，
不是"调接口"。

---

## 二、四条路径对比

### 路径 A：闲管家开放平台（官方服务商体系）

- **地址**：https://open.goofish.pro
- **性质**：闲鱼服务商/ERP 对接体系，域名 `goofish.pro`（区别于闲鱼官方 `goofish.com`）
- **能力**：商品增删改查、上下架、订单列表/发货、卡密、Webhook 回调
- **鉴权**：`app_id` + `app_secret` + `mch_id` + `mch_secret`，MD5 签名
- **客户端**：[thefreelight/xian-guanjia](https://github.com/thefreelight/xian-guanjia)（Python，MIT）
- **门槛**：⚠️ **需要服务商/商户资质申请，个人卖家基本拿不到凭证**
- **适合**：做 ERP、货源对接的商家，不是个人自用

> 注意：接口清单里**没有**"浏览量/想要数"这类流量数据，主要是商品和订单。

### 路径 B：闲鱼开放平台（小程序）

- **地址**：https://open.goofish.com
- **性质**：闲鱼官方，但是**小程序**体系
- **门槛**：❌ **明确不对外开放**，原文：

  > 「闲鱼小程序目前不对外公开开放申请，只面向闲鱼运营小二定向邀请的服务商，
  > 未经邀请的注册将不予通过。」

- 还要求企业账号、聚石塔部署、主体一致
- **结论**：**个人完全走不通，直接排除**

### 路径 C：浏览器自动化（Chrome 扩展 / Playwright）★ 最现实

这类项目用你**已登录的浏览器**操作，读页面数据。最接近你要的效果。

| 项目 | 方式 | 关键能力 | 语言 |
|---|---|---|---|
| [donggeai/xianyu-skills](https://github.com/donggeai/xianyu-skills) | Chrome 扩展 + 本地 CLI | `get-item-stats`（**浏览/想要数据**）、`list-my-items`、`analyze-competitors` | Python |
| [TnoobT/FishClaw_MCP](https://github.com/TnoobT/FishClaw_MCP) | Playwright + **MCP** | 商品发布、在售列表、市场调研 | Python |
| [superboyyy/xianyu_spider](https://github.com/superboyyy/xianyu_spider) | FastAPI + httpx | 关键词搜索、私信收发 | Python |

**路径 C-1：xianyu-skills（推荐先试）**

架构：Chrome 扩展 `Xianyu Bridge` 把 CLI 命令转发到你的浏览器执行。

```bash
# 安装
npx skills add donggeai/xianyu-skills
# 或手动
git clone https://github.com/donggeai/xianyu-skills.git
cd xianyu-skills && uv sync

# 加载 extension/ 目录到 chrome://extensions（开发者模式）
```

核心命令（**输出 JSON，方便脚本解析**）：

```bash
python scripts/cli.py check-login                  # 登录检查
python scripts/cli.py list-my-items                # 我的商品列表
python scripts/cli.py get-item-stats --item-id ID  # ★ 价格/浏览/想要
python scripts/cli.py analyze-competitors --keyword "口算题" --limit 10
python scripts/cli.py screenshot --output out.png  # 截图诊断
```

**为什么推荐**：只读自己的数据，`get-item-stats` 正好是你要的曝光/想要数；
JSON 输出能直接喂给本项目做复盘表。

**路径 C-2：FishClaw_MCP（可接进 DSH）**

DSH 原生支持 MCP（`packages/mcp/mcp-client`），理论上可以把它挂进来，
之后我就能直接调闲鱼工具。配置形如：

```yaml
- id: mcp-fishclaw
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: fishclaw
    transport: stdio
    command: python
    args: ['/abs/path/FishClaw_MCP/server.py']
```

> ⚠️ 但注意：FishClaw 的工具里包含 `publish_item`（发布）、`manage_item`（下架/删除）
> 等**不可撤销的写操作**，还有 `simulate_farming`（模拟养号）。
> 接入后我能调用它们 —— **需要你明确授权，且写操作必须逐次确认**。

### 路径 D：官方 API 文档里被误传的"商品详情 API"

网上有大量「闲鱼商品详情 API」文章（阿里云开发者社区等），
多数是**第三方数据服务商**包装的接口（按次收费），不是闲鱼官方。
数据来源不明、稳定性无保障、可能违反平台规则。**不建议**。

## 三、风险提示（必须看）

1. **所有自动化都操作真实账号**。平台风控会识别异常行为，可能限流或封号。
2. **只读相对安全，写操作风险高**。读自己的商品数据风险可控；
   自动发布、自动发消息、批量操作容易触发风控。
3. **Cookie/登录态会失效**，需要定期重新登录。
4. **不要多账号 + 自动化叠加**，那是风控红线（矩阵号判定）。
5. 各项目 README 都带了免责声明，说明作者也知道有风险。

---

## 四、建议的落地顺序

```
第 1 步：xianyu-skills 只读模式
  └─ 跑 check-login + list-my-items + get-item-stats
  └─ 拿到 JSON，验证能不能稳定读取

第 2 步：写个转换脚本
  └─ 把 JSON 转成本项目 ops/ 的复盘表格式
  └─ 每 3 天跑一次，自动更新曝光/想要数据

第 3 步（可选）：接 MCP 进 DSH
  └─ 让我能直接读闲鱼数据并给建议
  └─ 写操作单独授权

不建议做的：
  ✗ 自动发布商品（风控高危，且闲鱼网页端分类限制多）
  ✗ 自动发消息/自动回复（判机器人）
  ✗ 多账号批量自动化
```

## 五、最终采纳方案：xianyu-search（mtop 接口）

> 2026-10-08 审查源码 + 实测导入后确定。这是目前**最适合本机环境**的方案。

### 为什么选它（对比之前的浏览器方案）

| | xianyu-skills（之前看的） | **xianyu-search（采纳）** |
|---|---|---|
| 抓取方式 | Chrome 扩展 + 页面正则 | **mtop HTTP 接口 + 签名** |
| 无头 Linux | 要改造（撞 HeadlessChrome 拦截） | **原生支持，纯 HTTP 不碰浏览器** |
| 登录 | 扩展里的登录态 | **一次性扫码 / Cookie 导入，之后纯 HTTP** |
| 无桌面登录 | 不行 | **行：`login --cookie-stdin` 从别处导 Cookie** |
| 稳定性 | 靠正则抓页面文本，改版即挂 | 接口字段，相对稳定 |
| 代码质量 | 一般 | **28 个测试全过，有架构文档** |

### 架构（关键）

- 登录态 = 一个 cookie 文件（`~/.xianyu-data/storage_state.json`），
  核心是 `unb` cookie（登录后才出现）
- 登录**只在第一次**用浏览器（扫码），之后所有抓取走 `h5api.m.goofish.com` 的 mtop 接口
- mtop 签名：`md5(token & t & appKey & data)`，token 取自 `_m_h5_tk` cookie
  —— **已实测验证签名算法正确**
- 依赖只要 `httpx`（**本机已装 0.28.1**），playwright 仅登录时需要（走 cookie 导入可跳过）

### 它现在能做什么

- `search "关键词"` —— 搜**别人**的商品，Item 含 `want_num`（想要数）
- `analyze` —— 行情分析报告（价格分布、成色、地区、风险提示等）
- 落盘 SQLite + JSON，`export` 出 CSV

### 它现在不能直接做的（需要扩展）

- ❌ "我的商品列表"——它没实现这个 mtop 接口
- ❌ 单商品浏览数——Item 没有 `views` 字段（只有 `want_num`）

但这两点**可扩展**：MtopClient 是通用的，登录态在手就能调闲鱼的任意 mtop 接口。
"我的发布列表"和"商品详情含浏览数"的接口名，可从闲鱼网页版的请求里发现
（浏览器 F12 抓一次即可，不需要反复）。

### 在本机的落地步骤

```
1. 在你自己电脑（有浏览器的）登录 goofish.com
   → 用 Cookie-Editor 扩展导出 Cookie 字符串
   → 传到这台机器

2. 导入登录态（一次性）
   python scripts/xianyu.py login --cookie-stdin < cookie.txt

3. 验证抓取可用
   python scripts/xianyu.py search "口算题" --pages 1

4. 扩展"我的商品"接口（我来写）
   复用 MtopClient，调 mtop.taobao.idle.user.itemlist 之类
   → 喂给本项目的 xianyu_stats.py 做复盘表
```

- [x] 代码导入成功，签名算法正确
- [x] 28 个测试全过（解析/统计/存储/报告渲染）

## 六、之前无头浏览器方案的实测结论（备查）

> 用 CDP 驱动无头 Chrome 的方案，作为备选保留。xianyu-search 的 mtop 方案更优，
> 但这里记录实测事实以备万一。

- 无头 Chrome 能启动（`--headless=new --no-sandbox`，HOME 重定向到可写目录）
- 闲鱼会拦 HeadlessChrome UA，返回"非法访问"——用 CDP `setUserAgentOverride` 改桌面 UA 可绕过
- 未登录态下商品详情页**公开**显示"X人想要 / X万浏览"
- 但"我的商品列表"需登录态，且浏览器自动化路径更易触发风控

结论：**优先 mtop 方案，浏览器自动化仅作兜底**。
