# 闲鱼账号冷启动方案（0-30 天）

> 适用：全新或半新账号，目标从 0 做到稳定出单。
> 配套文件：[文案风格规范](../copywriting/STYLE.md) · [已上架清单](listings.md) · [订单记录](orders.md)

---

## 〇、先看结论

1. **先上已有的东西。** 口算练习内容包 7 个年级已生产完（322 个 PDF + 7 本答案册，5.5MB），
   文案已写，**不需要再开发任何东西**。冷启动第一批货就用它，不要等 exe 打包完。
2. **暂不开鱼小铺。** 普通号 50 件上限，冷启动阶段完全够用。鱼小铺按 1.6% 抽成且单笔不封顶，
   而闲鱼客服明确表示开通鱼小铺**不会获得额外流量倾斜**。等月成交稳定过 10 单、
   确实需要自动发货或多规格时再考虑。
3. **不搞"养号玄学"。** 平台没有官方"养号"机制，所谓养号本质是**避免触发风控**：
   新号短时间大量发布、大量私信、异地登录会被判定异常。做的是"像正常人一样用"，
   不是"刷数据"。
4. **虚拟品的生死线是合规，不是文案。** 一个违规下架能毁掉整个号的权重，
   红线清单见第五节，**上架前逐条过一遍**。

## 一、阶段一：账号基建（Day 0，约 1 小时）

### 必做
- [ ] **实名认证**：绑定本人身份证 + 支付宝，这是能收款的前提
- [ ] **芝麻信用授权**：影响买家信任，也影响后续开鱼小铺的资格（门槛约 650 分）
- [ ] **头像**：用真人感照片或干净的品牌图，不要用网图明星、不要用二维码
- [ ] **昵称**：带品类关键词，例如「小陈工具铺」「XX 软件小站」——昵称也进搜索权重
- [ ] **简介**：一句话说清做什么 + 交付方式。例：
      「程序员，做小工具和定制开发。虚拟品网盘发货，软件发 exe，交付后 7 天免费修 bug。」
- [ ] **收货地址/联系方式**：确认支付宝可正常收款

### 不做
- ❌ 资料里留微信/QQ/手机号（含谐音"薇❤"）——直接违规
- ❌ 昵称或简介写"全网最低""一手货源"这类词

### 为什么不能注册完立刻发商品
新号第一天就批量发布，容易被打上营销号标记，初始曝光池给得很少。
**Day 0 只做基建，不发商品。**

---

## 二、阶段二：正常使用期（Day 1-3）

这三天不发商品，只做一件事：**让账号看起来是个正常用户**。

每天花 10-15 分钟：
- 搜索你要卖的品类关键词（"口算题""小学口算练习"），浏览同类商品
- 收藏 2-3 个同行，看他们的标题怎么写、定价多少、首图什么样
- 观察同行销量和"我想要"数，反推这个品类的真实需求

**这三天的真实产出不是"权重"，是竞品情报。** 顺手记下：
- 卖得好的标题用了哪些关键词
- 主流价格带在哪
- 同行详情页有没有写清边界（大部分人没写，这是你的差异化）

> ⚠️ 不要互赞互关、不要刷"我想要"。这类行为一旦被识别，比不发商品更伤号。

## 三、阶段三：首批发品（Day 3-7）

### 节奏
**一天发 1-3 个，不要一次发满 50 个。** 新品上架本身有初始曝光，
分开发能把曝光摊到多天，也符合正常用户行为。

### 首批货顺序（按你现有库存排）

| 顺序 | 商品 | 理由 |
|---|---|---|
| 1 | 口算练习内容包 · 单年级款（二年级上） | 交付物就绪，0 成本，家长刚需 |
| 2 | 口算练习内容包 · 全年级打包 | 提价 SKU，承接买了单年级的复购 |
| 3 | 口算练习内容包 · 一年级下/三年级上 | 铺关键词，覆盖不同年级搜索 |
| 4 | 其余年级逐个补齐 | 每个年级都是一个独立搜索入口 |

**工具版（口算生成器 exe）先别上**，等 Windows 打包测完再发。
photo-sorter 文案还没写，优先级排后。

### 单条商品的发布检查表
- [ ] **标题**：关键词前置，≤30 字。前 15 字最关键
      （"小学二年级口算题"必须出现在最前面）
- [ ] **首图**：真实截图/打印实拍，清晰，图上 2-3 个标签（如"50份""2000道""含答案"）
- [ ] **多图**：至少 5 张 —— 封面、内容实拍、答案册、打印效果、发货说明
- [ ] **详情文案**：用 `copywriting/generated/商品/` 里已写好的，**一字不改直接用**
- [ ] **价格**：写具体金额，不写"面议"
- [ ] **库存**：虚拟品设足够库存，别设 1 件
- [ ] **发货方式**：网盘链接（**用文件夹形式，不要发压缩包**）

### 定价结构（三档）

```
引流款  一年级上（题量少）        ¥5.9   —— 拉"我想要"和浏览量
主推款  各年级单册                ¥9.9   —— 主力利润
打包款  1-4 年级 7 个版本全打包   ¥29.9  —— 提客单价，承接多孩家庭/托管班
```

> 刚上架的 3-5 天可以把主推款压到 ¥6.9 冲前几单和好评，
> 有销量和评价后再回调到 ¥9.9。**注意：不要用"标低价、实际卖高价"那套**，
> 闲鱼买家对这套很敏感，容易招差评。

## 四、阶段四：日常运营（每天 30 分钟）

### 每天固定动作

| 动作 | 频率 | 说明 |
|---|---|---|
| **擦亮** | 每天，分 2-3 批 | 早/午/晚各擦一批，不要同一时间全擦完。晚上 17:00-20:00 是高峰 |
| **上新品** | 每天 1-2 个 | 新品有初始曝光，是免费的流量来源 |
| **回复私信** | 5 分钟内 | 回复速度直接影响转化，慢回等于丢单 |
| **主动改标题** | 每 3 天 | 把没曝光的商品标题换一组关键词重发 |

> 擦亮规则平台改过几次，**以闲鱼 App 内当前实际入口和提示为准**，
> 不要照搬网上老教程。

### 咨询转化要点
- 用 `copywriting/generated/话术/` 里的话术模板，短、直接、给数字
- 买家问"只有二年级上吗" → 直接答"7 个年级都有，您要哪个年级我发对应的"
      （这是你比同行强的地方，同行大多只有一两个年级）
- 买家犹豫价格 → 推打包款，不要直接降价
- **不要为了成交做虚假承诺**（"永久更新""包学包会"），STYLE.md 里已列为禁用

### 前 5 单的处理
前几单优先保好评，不优先保利润：
- 发货快（拍下 5 分钟内发网盘链接）
- 主动附一句"打印有问题随时找我，7 天内免费重发"
- 收到货后不催好评（催评容易招反感），但把售后做到位

## 五、风险红线清单（虚拟商品，逐条过）

这是最容易被忽略、但代价最大的一节。

- [ ] **不留联系方式**：图片、文案、私信里都不放微信/QQ/手机号，谐音也不行
- [ ] **不发压缩包**：压缩包易被判违规，改用网盘**文件夹**分享
- [ ] **禁用词**："破解""永久""全网最全""一手"——上架前搜一遍自己的文案
- [ ] **截图打码**：资料截图里如果有书籍封面、ISBN 条码、他人水印，打码或裁掉
- [ ] **不用别人的素材**：内容包由 `kids-worksheet-gen` 程序生成，**零版权风险，
      这是你相对同行的核心优势，别去网上扒图凑数**
- [ ] **自动回复间隔 > 5 分钟**：回复太快会被判机器人（用工具的话尤其注意）
- [ ] **虚拟品售后写清**：详情页写明"虚拟商品发货后不支持退款"，减少扯皮
- [ ] **不碰盗版软件/课程/破解资源**：这是封号重灾区，一次就够

## 六、账号数量与类目策略（要不要开第二个号）

### 6.1 一个人能开几个号

- **上限**：闲鱼无独立注册体系，依托淘宝/支付宝实名。一个身份证最多认证 3 个支付宝账户，
  故个人实名闲鱼号**理论上限 3 个**（第三方实操经验，非官方明文，以实际为准）
- **一个手机号只能绑一个闲鱼号**，开第二个必须用独立手机号
- **企业主体**可开更多（一个营业执照对应多个支付宝账户），但需资质备案，不适合现阶段

### 6.2 多号的真实成本是风控，不是数量

- 同一设备/IP 登录 **超过 2 个**账号，且类目/文案/图片风格重合 → 判**矩阵号** → 限流/封号
- **借亲友身份开号是坑**：平台有人脸动态抽查，非本人实名账号在提现、纠纷、
  客服核验时会被**冻结资金**
- 多号需"一机一卡一号 + 网络隔离 + 人设差异化"，维护成本极高

### 6.3 结论：冷启动期只开 1 个号

理由：
1. 新号本身要 3 天基建 + 观察期，开两个 = **双倍冷启动成本**
2. 当前 SKU（7 个年级 + 少量工具）**撑不满一个号**，分开两边都单薄
3. 一个人精力有限，**两个半死的号不如一个跑通的号**

> 什么时候才分第二个号：某条线月成交稳定，且与主线**人群、话术、售后**完全两套时。
> 例如「定制开发」做大后独立成号（高客单、需谈需求、有季节性）。

### 6.4 垂直还是杂乱：先破误区

**闲鱼是单品推荐逻辑，不是店铺逻辑**（与淘宝的本质区别）。
每个商品独立竞争自己的搜索词，**不会因"类目杂"而整体降权**。
"杂货铺权重低"的说法在闲鱼被夸大了。

唯一真实影响是**账号人群标签**：类目跨度过大 → 推荐系统打不上稳定标签 →
**推荐流量**不精准。但**对搜索流量无影响**。

而本项目品类**全是搜索驱动**：

| 品类 | 买家搜索词 | 流量类型 |
|---|---|---|
| 口算内容包 | 口算题 / 小学口算练习 | 搜索 |
| 图片·PDF 工具 | 图片批量加水印 / PDF合并 | 搜索 |
| 嵌入式课设 | 单片机课程设计 / stm32毕设 | 搜索 + 私信 |

**结论：一个号混着放，影响很小。** 定制开发是典型"搜索+私信转化"型服务，
几乎不吃推荐流量，与成品混放完全可行。

### 6.5 真正要防的"杂乱"是自伤行为

不是类目多，而是**自己跟自己抢流量**：

- ❌ 同一商品换标题重复铺 → 判重复铺货
- ❌ 商品标题关键词互相重叠 → 内部竞争，稀释曝光
- ❌ 图片/文案高度雷同 → 图像识别 + 文本相似度会拦截

### 6.6 建议的号内结构

```
主力（走量、可复制）
├── 口算内容包 7 个年级          ← 每个年级一个独立搜索入口，标题不重复
└── 小工具 exe（水印/压缩/PDF）  ← 职场、自媒体人群

补充（高客单、搜索驱动）
└── 定制开发接单                ← 嵌入式课设/毕设、Python 脚本、Web
```

**人设统一**：简介写「程序员，做小工具、定制开发和打印资料」，一句话覆盖三类。

> 口算 PDF 与"程序员"人设看似跳，但文案已写明"题目由程序按课标范围生成"，
> 这是同行做不到的信任点，正好接上——**不要因为"人设不搭"就把它挪去新号**。

## 七、决策：要不要开鱼小铺

| | 普通号 | 鱼小铺 |
|---|---|---|
| 发布上限 | 50 件 | 300 件 |
| 单品库存 | 只能设 1 件 | 可自设库存 |
| 自动发货 | 不支持 | 支持 |
| 费率 | 基础 0.6% | 1.6%，单笔不封顶 |
| 流量倾斜 | — | **官方客服确认：无额外倾斜** |
| 门槛 | 无 | 芝麻分 ≥650、无违规，多为邀请制 |

**结论：冷启动阶段不开。**
理由：50 件上限对你现在的 SKU 数量（7 个年级 + 后续工具）完全够；
自动发货可以先用人工顶上（虚拟品拍下秒发链接，工作量不大）。
等**月成交稳定超过 10 单**、人工发货开始成为负担时再开。

> 补充：开通后有 7-15 天流量适应期，且监管更严，卖全新品可能需缴保证金。
> 不要为了"看起来专业"提前开。

## 八、数据复盘节奏

### 每 3 天看一次
- **曝光量**：所有商品都为 0 → 账号或文案有问题，先检查是否被限流
- **单商品曝光**：某个商品长期 0 曝光 → 换标题关键词 + 换首图重发

### 每 7 天看一次
- **有曝光无咨询** → 首图不够吸引，或价格高于同行 → 改首图/调价
- **有咨询无成交** → 话术问题或信任不足 → 补实名/芝麻信用展示，改话术
- **有成交** → 记录是哪个关键词进来的，把这个词铺到其他商品标题上

### 每 30 天
填 [listings.md](listings.md) 底部的「上架复盘要点」：
新上架数、下架数、最热销品类、转化最高的文案、淘汰候选。

## 十、和本项目其他部分的衔接

- **文案**：直接取 `copywriting/generated/商品/` 里已生成的，不用重写
- **新商品**：告诉我产品，我按 STYLE.md 生成文案并存档
- **上架登记**：每挂一个商品，告诉我，我登记进 `listings.md`（把待上架表里的行移到上架表）
- **成交记录**：每成交一单，告诉我，我记进 `orders.md`
- **选题**：新点子记进 `ideas.md`，按三条判据筛（边界/客观性/人群规模）

> 冷启动阶段最该做的一件事：**把口算内容包挂出去**。
> 东西已经做好了，晚一天上架就少一天曝光。
