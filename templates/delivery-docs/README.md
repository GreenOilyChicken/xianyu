# 交付文档模板

> 定制单交付时用这套模板写《使用说明》和《源码说明》，附在交付包里。
> 让客户看得懂、自己改得动、售后少扯皮。

---

## 一、使用说明（USE.md）—— 给客户看

```markdown
# {{app_name}} 使用说明

## 这是什么
{{one_line_description}}

## 怎么用

### 1. 准备
{{precondition}}

### 2. 运行
{{run_steps}}

### 3. 常见问题
| 问题 | 解决 |
|---|---|
| {{faq_q1}} | {{faq_a1}} |

## 注意
{{caveats}}

## 售后
交付后 7 天内免费答疑。联系方式：{{contact}}
```

## 三、交付清单核对（DELIVERY-CHECKLIST.md）—— 自己发货前用

```markdown
# 发货前核对

## 代码
- [ ] 源码完整，无临时/测试文件残留
- [ ] 无硬编码的密钥/账号/本机路径
- [ ] README.md 写清楚是什么、怎么跑
- [ ] 依赖版本锁定（requirements.txt / package.json）

## 文档
- [ ] 使用说明（USE.md）
- [ ] 源码说明（如约定交付源码）
- [ ] 部署文档（Web 应用必含）

## 验证
- [ ] 在干净环境跑过一遍
- [ ] 异常输入有友好提示
- [ ] 演示视频/截图就绪

## 售后
- [ ] 已告知售后边界（7天/范围）
- [ ] 已登记到 ops/orders.md
```

## 四、需求确认书（SPEC.md）—— 开工前跟客户确认

```markdown
# {{app_name}} 需求确认

## 一句话需求
{{one_line}}

## 功能清单（含边界）
| # | 功能 | 验收标准 |
|---|---|---|
| 1 | {{feature1}} | {{accept1}} |

## 不包含（明确排除）
{{exclusions}}

## 交付物
- [ ] {{deliverable1}}
- [ ] {{deliverable2}}

## 时间与费用
- 工期：{{days}} 天
- 总价：¥{{price}}
- 定金：¥{{deposit}}（开工前付）
- 尾款：¥{{balance}}（验收后付）

## 双方确认
客户：____________  日期：____
我方：____________  日期：____
```

> 用法：每接一单，复制对应模板到工具目录填好，跟客户确认后再开工。
> 这是防扯皮的关键文档，别省。
