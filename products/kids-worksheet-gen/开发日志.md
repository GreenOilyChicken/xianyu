## 2026-10-08 · 字帖生成器完成，复用架构扩品类（v1.1 第一步）

**背景**：重构方案提示词 1 规划的字帖生成器，是 kids-worksheet-gen 产品线的
第二个品类。选它优先做，是因为它**完全复用现有架构**（fonts.py / pdf_render 的
页眉风格 / main.py 的 CLI 结构），开发成本是所有候选里最低的；且和口算
**人群完全重叠**（小学低年级家长），可交叉销售。

**完成范围**：

| 模块 | 文件 | 说明 |
|---|---|---|
| 字帖渲染 | `src/zi_tie.py` | 新增 ~220 行：田字格渲染 + 三种模式 + 拼音 |
| CLI 子命令 | `src/main.py` | `--mode zitie`，加 `--chars/--char-file/--style/--pinyin` |
| 字表 | `assets/chars_3500.txt` | 内置 292 个常用字，可替换为完整国标字表 |
| 测试 | `tests/test_zitie.py` | 新增 38 项，**总计 136 项全绿** |

**★ 核心设计：田字格是"格 + 字"两层结构**

和口算的"题目网格"完全不同，所以渲染逻辑独立成 `zi_tie.py`，不复用
`pdf_render.render_sheet`。但**复用了 fonts.py 的字体探测**（同样的 Noto CJK
坑、同样的缺字校验），以及 `_draw_header` 的页眉风格保持一致。

**三种模式**：
- `miaohong` 描红：第一格印**灰色**范字（RGB 0.75），后几格空白供描写
- `linmo` 临摹：第一格印**黑色**范字，后面全空白供临写
- `hunhe` 混合：偶数行描红规则，奇数行临摹规则，交替

**字表设计**：
- `--chars "永和九年"` 直接指定字（按需生成）
- `--char-file` 从文本文件读，自动去重、只保留汉字（过滤标点空格）
- 都不指定时回退到内置 `assets/chars_3500.txt`（292 字精选起步集）
- 说明文件里注明可替换为完整国标 3500 字表

**验证方式**（全部程序化，不靠肉眼）：
- `python -m pytest` → **136 passed**（原 98 + 新 38）
- 三种模式各生成 PDF，pypdfium2 回读确认字符真的嵌入（不是空白方块）
- 拼音声调（如 `yǒng`）能从 PDF 文本提取，证明拼音渲染正确
- 多页分页正确（72 字 → 17 页），单页不打印页码
- 字表去重、非汉字过滤、空文件处理均有测试覆盖
- CLI 集成：`--mode zitie` 不影响口算默认行为（向后兼容测试）

**开发中注意的点**：
1. **拼音依赖**：提示词提到可选 pypinyin，但本版**不引入该依赖**——
   `CharSpec(char, pinyin)` 接受手填拼音，`--chars` 模式不带拼音。
   如需自动注音，后续可加 `--auto-pinyin` 调用 pypinyin。
2. **混合模式行号**：用**全局行号**判断描红/临摹，跨页保持交替规律，
   不是页内行号——否则换页时规律会错乱。
3. **`--out` 默认值**：改为 `default=None`，各模式分支各自设默认
   （口算→口算练习.pdf，字帖→字帖.pdf），避免模式间默认名冲突。

**产出物**：字帖 PDF 可直接打印。**这是工具线 A 的第二个产品品类。**

**当前状态**：
- ✅ 字帖生成器 CLI 可用，三种模式 + 拼音 + 字表加载
- ✅ 测试 136 项全绿
- ⏳ 仍卡在 PyInstaller 打包（需 Windows 机器，用户已确认有）

**下一步候选**：
1. **打包 exe**（口算+字帖一起打包，用户有 Windows 机器）—— 优先
2. 字帖内容包（线 B）：批量生成字帖 PDF 合集上架
3. 字帖上架文案
4. GUI 界面（提示词 2）
5. 竖式/脱式计算生成器

**已知待办**：

## 2026-10-08 · `--batch` 批量出卷完成，内容包产品线打通

**背景**：`--batch` 是"内容包"产品线（线 B）的生产函数。选它优先做，是因为
**内容包这条线完全不需要打包 exe** —— PDF 本身就是交付物，网盘一发即可，
绕开了"PyInstaller 必须 Windows"这个卡点。

**完成范围**：

| 模块 | 文件 | 说明 |
|---|---|---|
| 跨文件去重 | `src/core.py` | `generate_batch()` + `exclude` 参数 + `unique_capacity()` |
| 批量出卷 | `src/batch.py` | 新增 167 行，`run_batch()` / `BatchOptions` |
| 答案册 | `src/pdf_render.py` | `render_answer_book()`，多份汇总成一本 |
| CLI | `src/main.py` | `--batch/--sheets/--per-sheet/--answer-book/--each-answers/--capacity` |
| 测试 | `tests/test_batch.py` | 新增 34 项，**总计 98 项全绿** |

**★ 关键设计：容量预检（这是本功能最重要的发现）**

原方案打算靠随机采样硬撞去重，但实测发现**小范围题型的组合总数极小**：

| 题型 | 唯一题数上限 | 40题/份可出 |
|---|---|---|
| `g1a` 一年级上（20以内加减） | **361** | **9 份** |
| `g1a` + 只要进位/借位 | **108** | **2 份** |
| `g1b` 一年级下 | 9801 | 245 份 |
| `g2a` 二年级上 | 9882 | 247 份 |
| `g3b` 三年级下 | 8641 | 216 份 |
| `g3a` 三年级上 | 1470359 | 36758 份 |

如果不预检，用户要"一年级上 20 份"时会陷入近乎死循环的随机采样。
现在 `unique_capacity()` 精确算出上限，超限直接明确报错并告知可用份数，
新增 `--capacity` 命令可随时查询。

**验证方式**（全部程序化，不靠肉眼）：

- `python -m pytest` → **98 passed**
- 生产 50 份 × 40 题 = 2000 道，**从 PDF 回读**正则解析全部题目：
  `总题数 2000 / 唯一 2000 / 重复 0` ✅
- 答案册 12 页，正则统计答案条目 **2000 条**，与题量一致 ✅
- 性能：50 份 2000 题 **0.83 秒**（含 PDF 渲染）
- 四个题型各出 30 份 40 题，全部成功 ✅

**开发中修掉的问题**：

1. **超限时误建空目录** —— 原逻辑先 `mkdir` 再校验容量。
   已改为**先预检再建目录**，并加测试 `test_run_batch_over_capacity_raises_before_mkdir`。
2. **报错与横幅输出顺序错乱** —— stdout 缓冲导致报错跑到横幅前面。
   已把容量预检提到打印横幅之前，退出码统一为 3。

**产出物**：`out/内容包_二年级上/` —— 50 份 PDF + 1 本答案册，共 844KB。
**这个目录就是可以直接上架闲鱼的内容包交付物。**

**当前状态**：

- ⏳ 工具产品线（线 A）仍卡在 PyInstaller 打包（需 Windows 机器）

## 2026-10-08 · v1.0 骨架完成，口算题 PDF 闭环跑通

**选题决策过程**（记录一下，避免以后重复纠结）：

前几轮讨论过 Word 批量替换、电子发票整理、照片地理归档，都被否掉，理由如下：
- **Word 批量替换** ❌ 边界由「客户业务流程」定义，替换规则/格式保留人人不同，必然转定制单
- **电子发票整理** ⚠️ 边界客观（国标），但客户是代账公司/财务，**人群小**，天花板低
- **照片地理归档** ✅ 边界客观，但竞品密（Easy Duplicate Finder 等），且用户已有 photo-sorter 完整版
- **口算题生成** ✅ **选定** —— 边界由数学定义+课标定义，人群上亿，竞品几乎全是网页版

**确立的选题判据**（两条，写下来复用）：
1. 边界由「文件格式/学科标准」定义 → 可通用；由「客户业务流程」定义 → 必然定制
2. 配置项是「客观约束」还是「主观偏好」

**完成范围**：

| 模块 | 文件 | 状态 |
|---|---|---|
| 出题核心 | `src/core.py` | ✅ 7 个年级题型，纯逻辑无 reportlab 依赖 |
| A4 排版 | `src/pdf_render.py` | ✅ 页眉/网格/分页/答案页 |
| 中文字体 | `src/fonts.py` | ✅ 跨平台探测 + 缺字校验 |
| CLI 入口 | `src/main.py` | ✅ argparse，8 个参数 |
| 测试 | `tests/` | ✅ **64 项全绿** |

**★ 实测踩到的关键坑（已写进方案）**：

`reportlab` **只支持 TrueType 轮廓字体，不支持 PostScript/CFF 轮廓**。实测：

```
Noto Sans CJK (NotoSansCJK-Regular.ttc) → ❌ TTFError: postscript outlines are not supported
文泉驿正黑 (wqy-zenhei.ttc)              → ✅ 正常
```

这个坑很隐蔽——大部分 Linux 发行版默认装的是 Noto CJK，直接用会崩。
对策：候选字体表**故意排除 Noto CJK**，每个候选实际注册一次验证，再校验字形覆盖
（缺字会渲染成空白方块，比报错更难发现）。支持 `KIDS_FONT_PATH` 环境变量兜底。

**开发中修掉的真 bug**：

- 答案页原本画在题目页上**重叠**（120题只出 3 页，答案盖在第 3 页）。
  已改为答案**独立成页**附在最后，并加测试 `test_answer_page_is_separate` 锁死。

**验证方式**：

- `python -m pytest` → 64 passed
- 各年级生成 200 道，程序化校验：无负数、不超上限、除法必整除、同页无重复 → 全部通过
- PDF 用 pypdfium2 提取文本回读，确认中文真的嵌入（不是空白方块）
- 渲染成 PNG 做墨迹密度分析，标题带 3.41% vs 空白带 0%，确认中文画出

**环境注意**：
- 系统 Python 3.13.5，venv 缺 ensurepip（Debian 拆分包），改用 `pip install --target ./libs`
- 装依赖走清华镜像（`-i https://pypi.tuna.tsinghua.edu.cn/simple`），默认 pypi 会超时

**当前状态**：CLI 版可用，能出卷。**尚未打包成 exe，尚未上架。**

**下一步候选**：
1. **打包 exe 并在干净 Windows 上测**（含中文字体探测，这是最大风险点）—— 优先
2. 用 `--batch` 生产内容包（提示词 3），双线变现的线 B
