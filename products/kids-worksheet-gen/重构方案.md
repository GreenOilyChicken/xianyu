## 一、为什么是这个选题

### 选题定位

| 维度 | 本方案 | 说明 |
|---|---|---|
| 目标人群 | 小学生家长 | 上亿量级，付费意愿最强的品类之一 |
| 痛点 | 老师让练口算，家长自己出题/买练习册 | 高频、重复、有明确时间点（每晚） |
| 交付 | 本地 exe，生成 PDF，打印即用 | 无需注册、无需联网、不限次数 |
| 价格 | 工具 ¥9.9–19.9 / 内容包 ¥5.9–9.9 | 双线变现 |

### 为什么不做「Word 批量替换」那类选题

判断一个选题能不能做成**通用成品**（而不是被迫转定制单），用两条判据：

1. **边界由谁定义**：由「文件格式 / 学科标准」定义 → 可通用；由「客户业务流程」定义 → 必然定制
2. **配置项性质**：是「客观约束」还是「主观偏好」

对照：

| 选题 | 边界来源 | 配置项 | 结论 |
|---|---|---|---|
| Word 批量替换 | 客户业务 | 主观（替换什么、格式怎么保） | ❌ 必然转定制 |
| 电子发票整理 | 国标 | 主观（命名习惯） | ⚠️ 偏 B 端，人群小 |
| **口算题生成** | **数学定义 + 课标** | **客观（年级 → 范围唯一）** | ✅ **可通用** |
| 字帖生成 | 国标字表 | 客观 | ✅ 可通用 |

口算题的正确答案由数学定义，出题范围由课标定义——**没有"你们家想怎么出题"的空间**。这是它能做成通用成品、而不是又一个定制单的根本原因。

### 为什么竞品打不过

搜到的竞品（[AI手抄报](https://www.9k9k.com/app/80149.html)、[Canva 手抄报](https://www.canva.cn/create/patriotic-handwritten-newspapers/) 等）**几乎全是网页版/App**：

| 维度 | 网页工具 | 本方案 |
|---|---|---|
| 联网 | 必须 | **不需要** |
| 注册 | 多数要 | 不需要 |
| 次数限制 | 常有 | 无限 |
| 广告 | 有 | 无 |
| 速度 | 等加载 | 秒出 |

家长的真实场景是：**晚上在家，打印出来明天用**。"本地 exe、双击即用、断网能用"对网页工具是降维打击。

## 二、产品线设计（一套核心，两条变现）

```
                    ┌─────────────────────────┐
                    │   教育内容生成核心库      │
                    │  core.py  出题逻辑       │
                    │  pdf_render.py  排版     │
                    │  fonts.py  中文字体      │
                    └───────────┬─────────────┘
                                │
              ┌─────────────────┴─────────────────┐
              ▼                                   ▼
    ┌──────────────────┐              ┌──────────────────────┐
    │  线A：卖工具      │              │  线B：卖内容包         │
    │  口算题 exe       │              │  口算练习 PDF 合集      │
    │  家长自己出题      │              │  直接打印，不用装软件    │
    │  ¥9.9–19.9       │              │  ¥5.9–9.9（自动发货）  │
    └──────────────────┘              └──────────────────────┘
              │                                   │
              └────────── 同一份代码产出 ──────────┘
```

**关键**：线 B 的内容包是**程序自己生成的**，不是采集或购买他人素材。

- ✅ 零版权风险（对比"中小学故事100首"这类采集他人版权内容）
- ✅ 零边际成本，可无限生成、无限铺量
- ✅ 拿到虚拟资料"上架当天可能出单"的速度

这解决了纯虚拟资料生意的最大问题——**版权**，同时保留它的体量和见效速度。

## 三、技术选型（已实测验证）

| 层 | 技术 | 状态 |
|---|---|---|
| 语言 | Python 3.9+ | ✅ 已用 3.13.5 验证 |
| PDF 生成 | `reportlab` 5.0.1 | ✅ 已验证 |
| 图像/字体处理 | `pillow`（reportlab 依赖） | ✅ 已验证 |
| 中文字体 | 系统 TrueType 字体，自动探测 | ✅ 已验证 |
| 打包 | PyInstaller `--onefile` | 待验证 |
| 测试 | `pytest` | ✅ 64 项通过 |
| PDF 校验 | `pypdfium2`（仅开发期用） | ✅ 已验证 |

**不引入的依赖**：不用 matplotlib（体积大、出图非排版）、不用 wkhtmltopdf（需外部二进制）、不用 LaTeX（部署地狱）。`reportlab` 是纯 Python + Pillow，打包最稳。

### ★★ 实测踩到的坑（必须写死，否则换台机器就崩）★★

**reportlab 只支持 TrueType 轮廓（glyf）字体，不支持 PostScript/CFF 轮廓。**

实测结果：

```
Noto Sans CJK  → ❌ TTFError: postscript outlines are not supported
文泉驿正黑      → ✅ 正常
```

所以：
- 候选字体表里**故意不放 Noto Sans/Serif CJK**
- 每个候选字体都**实际注册一次做验证**，失败就跳过
- 还要校验**字形覆盖**（缺字会渲染成空白方块，比报错更隐蔽）

`fonts.py` 已完整实现这套探测 + 校验逻辑，并支持环境变量 `KIDS_FONT_PATH` 手动兜底。

## 四、项目结构

```
kids-worksheet-gen/
├── README.md              # 上架文案（后续用 gen_copy 生成）
├── specs.md               # 功能清单（自用）
├── 重构方案.md             # 本文件
├── 开发日志.md             # 进展记录
├── requirements.txt
├── pytest.ini
├── build.sh               # PyInstaller 打包
├── src/
│   ├── main.py            # CLI 入口（argparse）
│   ├── core.py            # ★ 出题核心（纯逻辑，无 reportlab 依赖）
│   ├── pdf_render.py      # ★ A4 排版渲染
│   └── fonts.py           # ★ 跨平台中文字体探测
├── tests/
│   ├── test_core.py       # 出题逻辑测试
│   └── test_pdf.py        # 渲染 + 字体测试
├── libs/                  # 本地依赖（开发用，不进 git）
└── out/                   # 生成的 PDF
```

**分层原则**：
- `core.py` **不 import reportlab**，纯逻辑，可单测、可复用于任何输出格式
- `pdf_render.py` 只管排版，不关心题目怎么来的
- `fonts.py` 独立，字体问题只在这一处解决

| 功能 | 状态 |

| 出题数学正确性（无负数、不超上限、除法必整除） | ✅ 64 项测试 |
| 同页不重复题目 | ✅ |
| 进位/借位筛选（`--carry yes/no/any`） | ✅ |

| 多页自动分页 + 页码 | ✅ |
| 参考答案独立成页 | ✅ |
| 中文渲染（含缺字校验） | ✅ |
| 固定随机种子复现同一套题 | ✅ |

### 已支持的题型

| 代码 | 年级 | 说明 |
|---|---|---|
| `g1a` | 一年级上 | 20以内加减，结果≤20 |
| `g1b` | 一年级下 | 100以内加减 |
| `g2a` | 二年级上 | 100以内加减 + 九九表内乘法 |
| `g2b` | 二年级下 | 100以内加减 + 表内除法 |
| `g3a` | 三年级上 | 万以内加减 + 两位数乘一位数 |
| `g3b` | 三年级下 | 两位数乘两位数 + 除数是一位数 |
| `g4a` | 四年级上 | 三位数乘两位数 + 除数是两位数 |

### 用法

```bash
# 二年级上，40 题，4 列
python src/main.py --grade g2a --count 40 --out 口算练习.pdf

# 只要进位题（专项训练）
python src/main.py --grade g1b --count 60 --carry yes

# 带答案（家长批改用）
python src/main.py --grade g3b --count 40 --answers

# 作答括号
python src/main.py --grade g1a --count 30 --blank "（　　）"

# 查看所有题型
python src/main.py --list-grades

# ★ 批量出卷（内容包生产）：50 份 × 40 题，跨份全局不重复，附总答案册
python src/main.py --batch --grade g2a --sheets 50 --per-sheet 40 --answer-book

# ★ 查询题型出题上限（批量前预检，避免超限）
python src/main.py --grade g1a --capacity
```

### ★★ 出题容量上限（做内容包必看）★★

每个题型的**唯一题目总数是有上限的**，小范围题型尤其要注意。
`--capacity` 可随时查询，实测数据：

| 题型 | 唯一题数上限 | 40题/份可出份数 |
|---|---|---|
| `g1a` 一年级上（20以内加减） | **361** | **9 份** |
| `g1a` + 只要进位/借位 | **108** | **2 份** |
| `g1b` 一年级下 | 9801 | 245 份 |
| `g2a` 二年级上 | 9882 | 247 份 |
| `g2b` 二年级下 | 9873 | 246 份 |
| `g3a` 三年级上 | 1470359 | 36758 份 |
| `g3b` 三年级下 | 8641 | 216 份 |
| `g4a` 四年级上 | 89820 | 2245 份 |

**做内容包的策略**：
- 一/二年级（`g1a`/`g1b`/`g2a`/`g2b`）题量有限，**做 30–50 份即可**，
  别硬凑上百份；或把每份题数降到 30 题
- 三/四年级（`g3a`/`g3b`/`g4a`）容量充足，可放心做上百份
- 超限时程序会明确报错并告知可用份数，不会静默截断

**实测性能**：50 份 × 40 题 = 2000 道，含 PDF 渲染 **0.83 秒**。
