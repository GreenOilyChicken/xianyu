# 照片按省市分类导入器 · Flutter 跨平台重构方案

> 从零用 Flutter 重构。桌面（Win/Mac/Linux）+ 安卓（手机A→手机B WiFi 扫码直连）。
> 一套 Dart 代码，桌面和安卓共享同一个核心库。
> 本文件是技术方案 + Cursor 起手提示词，用 Cursor 开发时对照。

---

## 一、产品定义（已确认）

### 核心设计：两个独立功能

产品拆成**两个可独立使用的功能**，用户各选各的，不强绑：

| 功能 | 做什么 | 输入 | 输出 |
|---|---|---|---|
| **功能1：传输** | 把照片从一台设备搬到另一台 | 选源设备照片 | 存到目标设备指定目录（不分类） |
| **功能2：分类** | 把照片按省市地理归档 | 选本地文件夹 | 按 省/市 目录结构归档 |

**关键约束（已确认）**：
- 传输完成后**不自动触发分类**，两功能彻底解耦
- 分类功能的输入是**选本地文件夹**（扫里面所有照片）
- 用户可以单用功能1（只想换机搬照片）、单用功能2（照片已在电脑想整理）、或组合用

### 两个端

| 端 | 功能1（传输）怎么做 | 功能2（分类）怎么做 |
|---|---|---|
| 桌面 | 通过 ADB 把安卓手机相册导到电脑指定目录 | 选电脑本地文件夹，按省市分类 |
| 安卓 | 手机B 开热点/WiFi 挂接收服务 → 手机A 扫码连过来发 | 选安卓本地文件夹，按省市分类 |

**交互流程（安卓传输）**：手机 B 点"开始接收"→ 生成二维码（含 IP+端口）→ 手机 A 扫码连接 → A 选照片发送 → B 接收存到指定目录（不分类）。

**统一卖点**：按拍摄地省市自动分类 + 离线地理编码（不联网不传图保隐私）。

## 二、技术栈（定死，别再动摇）

| 层 | 技术 | 理由 |
|---|---|---|
| 框架 | **Flutter 3.x** | 一套 Dart 覆盖桌面+安卓，安卓体验最原生 |
| 状态管理 | **Riverpod 2** | Flutter 生态最成熟、类型安全、可测试 |
| 桌面传输（ADB） | 随包带三平台 adb 二进制，`Process` 调用 | adb 官方有 Win/Mac/Linux 版 |
| 安卓传输 | TCP socket + 二维码连接 | 不走云，扫码免输 IP |
| 文件/相册访问 | 桌面用 `dart:io`，安卓用 `photo_manager` | 各平台最成熟方式 |
| EXIF/GPS | `exif` 包 | Dart 纯实现，跨平台读 EXIF |
| 地理编码 | **`maps_toolkit` 的 `PolygonUtil.containsLocation` + 中国省市 GeoJSON 数据** | 不造轮子：算法用 Google port 的成熟库，数据用现成免费 GeoJSON。不联网，跨平台（含桌面），精确（边界附近不归错） |
| 本地存储 | `sqflite` + 文件系统 | 缓存地理编码结果、去重哈希 |
| 路由 | `go_router` | Flutter 官方推荐路由 |

## 四、关键技术点

### 1. 两个功能的解耦

- **功能1 传输**：只管搬照片，存到目标目录就结束。ViewModel 里**不调用** core 的 PhotoClassifier。
- **功能2 分类**：只管读本地文件夹、调 core 归档。不关心照片从哪来（ADB 来的 / WiFi 收的 / 本来就在的）。
- **唯一共享**：core 库里的 model（Photo）和工具（HashDedup 可选用于传输去重）。
- 首页给两个功能入口卡片，用户点哪个进哪个。

### 2. 桌面 ADB 随包分发（功能1桌面端）

```
assets/adb/
  windows/adb.exe + AdbWinApi.dll + AdbWinUsbApi.dll
  macos/adb          ← 要 chmod +x
  linux/adb          ← 要 chmod +x
```
- 运行时按 `Platform` 选对应路径
- **Mac 坑**：首次 adb 被 Gatekeeper 拦，提示用户右键打开一次
- **Linux 坑**：USB 访问要 udev 规则，首版可不支持 Linux
- 桌面"传输"功能：选源（连了 ADB 的安卓手机相册）→ 选目标目录 → 拉取，不分类

### 3. 安卓二维码直连传输（功能1安卓端）

```
手机B（接收方）：
  1. 进"传输/接收"页 → 点"开始接收" → 启动 TCP ServerSocket 监听 0.0.0.0:8888
  2. 取本机局域网 IP（连 WiFi 取 wlan0 IP / 开热点取热点网段 IP）
  3. 生成二维码：内容 = "photosorter://<IP>:8888"
  4. 展示二维码 + "等待连接..." 状态
  5. A 连上后，接收照片存到用户选的目录（不分类）
  6. 进度展示：已接收张数 / 总数

手机A（发送方）：
  1. 进"传输/发送"页 → 用 mobile_scanner 扫二维码 → 解析出 IP:port
  2. 连接 TCP Socket
  3. 选要发的照片（photo_manager 读相册）
  4. 逐张发送：先发 header（文件名+大小+EXIF时间），再发二进制
  5. 进度展示：已发送张数 / 总数 / 当前文件
```

**断点续传**：每张传完记一下，断了下次从断点续。首版可不做，先做能传。

### 4. 分类功能（功能2，两端共用一套 UI 逻辑）

```
分类页流程：
  1. "选文件夹"按钮 → 调 directory_picker_service 选本地目录
  2. 扫描该目录所有 jpg/jpeg（递归子目录可选）
  3. 显示扫描结果：共 N 张，其中 M 张有 GPS
  4. "开始分类"按钮 → 调 core PhotoClassifier
  5. 进度：已处理/总数/当前文件名 + "正在识别: 广东省深圳市..."
  6. 完成：显示归档结果摘要（省→张数列表），可点开看目录
  7. 无 GPS 的归到 "未定位/" 子目录
```

桌面和安卓共用同一个 `classify_screen.dart`，只有"选文件夹"按钮背后的 service 实现不同（桌面用原生文件选择器，安卓用 SAF/系统选择器）。

### 5. 离线地理编码（core，重要）

**不造轮子**：算法用现成库，数据用现成 GeoJSON，自己只写业务胶水代码。

**算法库**：`maps_toolkit`（pub.dev/packages/maps_toolkit，kb-apps.com 维护，verified publisher）
- Google 的 `android-maps-utils` 的 Dart port，成熟稳定，4 万+周下载
- 关键 API：`PolygonUtil.containsLocation(LatLng point, List<LatLng> polygon)` —— 点-多边形判断
- **全平台**：Android/iOS/Linux/macOS/Web/Windows 都支持（这点决定桌面能用）
- API 已确认可用，无需开工前验证

**为什么不选 `flutter_z_location`**：它底层也是用 `maps_toolkit`，但
- ❌ 仅 Android/iOS，桌面不支持（你的产品要桌面三平台）
- ❌ 3 年没更新（0.0.9，2021），unverified publisher
- ❌ 数据捆绑死（pikaz-18 数据源 3 年没更新），行政区划可能过时
- 等于用了 `maps_toolkit` 的算法但加了平台和数据限制——不如直接用 `maps_toolkit`

**为什么不选 `geocoder_offline`**：k-d tree 最近邻算法，省界附近会归错省，精度不够。

**为什么不选 `geocoding`**：调在线 API，不联网不能用，违背"离线保隐私"卖点。

**数据**：
```
assets/geo/china_provinces.geojson   ← 中国省界多边形（阿里 DataV 免费下载）
```

**流程**：
1. 启动时解析 GeoJSON，把每个省的多边形顶点转成 `List<LatLng>`，建省界索引
2. 拿到照片 GPS 坐标 → 遍历各省多边形 → 调 `PolygonUtil.containsLocation` 判断落在哪个省
3. 用 `dart:isolate` 在后台算，别卡 UI
4. **缓存**：同坐标不重复算，存 sqflite（lat,lon → province）
5. 无 GPS 的照片归到"未定位"目录

**数据来源**：阿里云 DataV GeoAtlas（搜索"DataV GeoAtlas"或访问 datav.aliyun.com/portal/school/atlas/area_selector），免费下载中国省市边界 GeoJSON。

### 6. EXIF/GPS 读取（core）

`exif` 包读 JPEG 的 EXIF，拿 GPSLatitude/GPSLongitude。
注意：视频的 GPS 在 MP4 元数据里，`exif` 包不读视频——**首版只做照片，视频后续加**。

### 提示词 2：实现 core 分类逻辑

```
实现 lib/core/ 下的跨平台照片分类逻辑。这些代码桌面和安卓共享，必须纯 Dart，不引用任何平台插件。

1. PhotoMetadataReader（core/exif/photo_metadata_reader.dart）
   - readGps(File) → (lat, lon) 或 null
   - readDateTime(File) → DateTime（拍摄时间）
   - 只处理 JPEG，视频返回 null

2. GeoCoder（core/geo/geo_coder.dart）
   - 用 maps_toolkit 包（pubspec 加 maps_toolkit: ^3.1.0 依赖）
   - 启动时加载 assets/geo/china_provinces.geojson，解析每个省的多边形顶点为 List<LatLng>，建索引
   - code(double lat, double lon) → GeoInfo{province, city?}
   - 调 PolygonUtil.containsLocation(LatLng(lat,lon), 省多边形) 判断坐标属于哪个省（不自己写算法）
   - 在 isolate 里跑，不卡 UI
   - 缓存：同坐标不重算（sqflite 存 lat,lon → province）

3. PhotoClassifier（core/classify/photo_classifier.dart）
   - classify(List<Photo> photos, String outputRoot) → Map<Photo, String>
     返回每张照片归到的目标路径，如 "输出/广东省/深圳市/IMG_001.jpg"
   - 无 GPS 的归 "输出/未定位/"
   - 文件名冲突自动加序号
   - 注意：这个类只做分类，跟"传输"功能无关

4. HashDedup（core/dedup/hash_dedup.dart）
   - 按文件内容 SHA256 去重
   - 重复的只返回第一次出现的

5. 写单元测试覆盖：
   - 有 GPS 照片归到正确省
   - 无 GPS 照片归到"未定位"
   - 重复照片只留一份
   - 坐标缓存命中不重算
```

### 提示词 3：功能1 - 传输（桌面ADB + 安卓WiFi）

```
实现功能1"传输"，桌面和安卓两种实现，但 UI 共用入口。

【桌面端 - ADB 导入】lib/data/services/adb_service.dart + features/transfer/send/
AdbService：
- adb 二进制随包分发，放 assets/adb/{windows,macos,linux}/
- 运行时按 Platform 选对应路径
- Mac/Linux 首次运行 chmod +x
- 方法：
  - isDeviceConnected() → bool（adb devices）
  - listPhotos() → List<String>（adb shell find /sdcard/DCIM 下的 jpg）
  - pullPhoto(remotePath, localPath) → 拉到本地
SendViewModel（桌面）：
- 选源：检测连了ADB的安卓手机
- 选目标：用户选本地目录
- 逐张 pull 照片到目标目录
- 状态：idle/listing/importing/done/error
- 进度：已处理/总数/当前文件名
- 支持取消
- ★不调用 PhotoClassifier，传完就结束

【安卓端 - WiFi 扫码直连】lib/data/services/wifi_transfer_service.dart + features/transfer/{send,receive}/
Receiver（手机B）：
- start() → 启动 ServerSocket 监听 0.0.0.0:8888
- 取本机局域网 IP
- 生成二维码："photosorter://IP:8888"
- onConnect：A 连上后逐张接收
- ★接收的照片存到用户选的目录，不分类
- 进度回调：已接收/总数
Sender（手机A）：
- connect(ip, port) → 连 TCP
- sendPhotos(List<Photo>) → 逐张发：header + 二进制
- 进度回调：已发送/总数
MobileReceiveScreen（B）：开始接收按钮 + 二维码 + 等待状态 + 接收进度
```
