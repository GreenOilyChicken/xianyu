## 2026-10-07 · 功能1「传输」完成 + 安卓 SAF 确认

**进展**:
- ✅ **功能1「传输」已完成**(桌面 ADB 导入 + 安卓 WiFi 扫码直连,两端打通)
- ✅ **安卓 SAF 问题已确认**:file_picker 选目录返回的是 `content://` tree URI,**不是真实路径**

**当前任务**:安卓 SAF content URI 适配(收尾功能2)
- 方案A(推荐):MethodChannel + ContentResolver 流式读,保住"选任意文件夹"卖点
- 方案B(退路):改用 photo_manager 列相册,功能收窄
- 选 A,详见下方给的适配方案(SAF适配提示词.md)

**扫描格式范围:已定 C(全格式+视频)**
- 决策:支持 JPEG/HEIC/PNG/WebP/RAW + MP4/MOV 视频
- 实现:换掉 `exif` 包,改用 `media_metadata_plus`(Rust 底层,统一 API,全平台)
  - 一个包替代 exif + 解决 HEIC + 解决视频,GPS 统一从 .gps?.lat 取
  - API:MediaMetadata.read(path) → 统一模型,逻辑几乎不变
- ⚠️ **三个代价**:
  1. 开发机要装 Rust 工具链(rustup)才能 build;产物带 Rust 动态库,体积大几 MB
  2. **SAF 适配变复杂**:media_metadata_plus 的 read() 吃文件路径,不认 content:// URI → 安卓 SAF 要先做"content URI→临时文件"转换,或验证它是否支持流输入
  3. PNG/WebP/GIF 仍基本无 GPS,列出来归未定位
- ⚠️ **开工前必做小验证**:安卓上拿 content URI 试 MediaMetadata.read(),确认能否直接吃
- listImages 过滤放宽:image/* + video/mp4 + video/quicktime,靠 magic bytes 判断更准
- 桌面先行(无 SAF 问题),安卓 SAF 适配跟上

**产品形态**:两个功能核心都已实现,剩下安卓分类的 SAF 适配是最后收尾。
